# Ties don't ship (my rule for skill edits)

**Posted by u/Secret-Agentt19 on 2026-09-29 · 8 points (50% upvoted) · 0 comments**

Hermes keeps updating a single line in a skill and when you check, it isn't clearly better. The complaint is really about what counts as better, and the fix I use is deciding that before the edit lands.
I run reef under Hermes and it puts a gate in front of every proposal. One edit to one entry of the tree, or nothing. The candidate and the current tree each play every task on a short list once; the verdict is wins / losses / ties. In the tutorial that's three coding tasks, a point if the exact answer stands alone on the last line, so a verdict looks like 1 / 0 / 2. The edit publishes only when it wins more than it loses. A tie isn't a win, so the one-line tweak that changes nothing measurable doesn't ship, and the one that makes a failing task pass does.
The already-passing tasks on the list are your regression set. And this gate sits in front of reef's proposals, not Hermes's own skill updates; those are a second writer, separate question.
The useful exercise for a skill Hermes keeps touching: write down the three tasks you'd grade it on. If you can't, the loop can't either.
