# Obsidian llm wiki or other memory layers for personal assistent

**Posted by u/Havlenp on 2026-09-29 · 5 points (100% upvoted) · 13 comments**

I’m in the process of setting up Hermes. So far its pretty cool. My intention is to use it as a personal assistant. I don’t intend to use it for coding tasks, at least not yet.
At work I have set up an llm-wiki for my coding harness, and seen great results. It easily finds information and understand tricky problems we have debugged earlier. I want the same for my personal assistant. I want it to evolve and remember not just the high level stuff, but details we discuss without me having to point it out.
I attacked the task with the hammer I know, an llm-wiki in obsidian. Benefit is persistence if I change out the agent or make multiple. But I have since realized people use honcho, hindsight etc for this instead. It seems like these tools solves an issue i have had with the obsidian setup, where it isnt consistent with ingesting data into the wiki.
I have tried reading up on all this but it’s hard to know the best path without trying it all, and I don’t have the energy and time to test it all. So I am looking for your insight
- are these memory systems a noticeable improvement to default memory handling.
- are they better than a handrolled obsidian vault? Especially in automation. Issue with llm wiki often is that you have to point out what to capture
- which one is easiest and cheapest to go with
- what do you use and why
My agent is hosted on a hetzner vps. Might move it to a private server at some point, but wanted to test if I actually end up using it day to day.
