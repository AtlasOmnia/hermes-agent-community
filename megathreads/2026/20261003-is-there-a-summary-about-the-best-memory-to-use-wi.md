# Is there a summary about the "best memory" to use with Hermes?

**Posted by u/fttklr on 2026-10-03 · 10 points (91% upvoted) · 34 comments**

I have been looking at the different options offered by Hermes Desktop and there are many; so it is not exactly immediate to figure this out.
For starters, I am aware that Hermes does use its text files in each profile to save important info you tell it to save, and at certain points it "learn" some facts and add those to its memory. Problem is those are open text files that can be seen and edited, and the second issue is that these go in every prompt you send; with all the related issues I don't need to point out.
As such I am aware that Hermes can use other memory systems that are more akin to a standard RAG system based on either a SQL database or a pure vector DB approach. From the past I have been using Mnemosyne, but it does not show up in the list that Hermes Desktop has, and I am not familiar with the other options offered (besides Honcho, which while it is great on paper, is tied to the Honcho APIs and I am not keen to invest time in train a system that is tied to something I cannot easily convert if I move to another platform).
While many people are happy to just use the standard MD files for their workflow in Hermes, I am going for a more in depth optimiziation and would appreciate some suggestions about the best memory frameworks supported by Hermes Desktop (besides Honcho, which I am familiar with already). If you use one and have a workflow that goes beyond just using a machine to run agents, I would really benefit from your insights. Thanks in advance
